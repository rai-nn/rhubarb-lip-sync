⏺ Rhubarb Lip-Sync Codebase Analysis

  Purpose: This is an automatic lip-sync animation system that analyzes audio recordings, performs speech recognition, and generates synchronized mouth shape animations for 2D character animation.

  Core Architecture

  1. Multi-Stage Processing Pipeline:
  - Audio Processing (audio/): Reads audio files (WAV/OGG), performs voice activity detection, sample rate conversion, and DC offset removal
  - Speech Recognition (recognition/): Two recognizer implementations:
    - PocketSphinx-based recognizer for word-level recognition
    - Phonetic recognizer using acoustic models to detect phonemes (sounds)
  - Animation Generation (animation/): Converts phonemes to mouth shapes through multiple stages:
    - Shape rule generation from phonemes
    - Rough animation creation
    - Timing optimization
    - Pause animation
    - Tweening (in-between frames)
    - Static segment avoidance

  2. Core Data Models:
  - Phone (core/Phone.h): Represents phonemes using Arpabet notation (46 different sounds)
  - Shape (core/Shape.h): Nine mouth shapes (A-F basic Hanna-Barbera shapes, plus G, H, X extended)
  - Timeline (time/Timeline.h): Template-based temporal data structure for managing timed events

  3. Key Design Patterns:
  - Pipeline Pattern: Sequential processing stages with clear interfaces
  - Strategy Pattern: Multiple recognizers and exporters with common interfaces
  - Template Metaprogramming: Extensive use for timeline data structures
  - Factory Pattern: Creating exporters and recognizers based on runtime configuration

  4. Export Formats (exporters/):
  - JSON, XML, TSV, and DAT formats for various animation software
  - Supports After Effects, Moho, OpenToonz, Spine, Vegas Pro

  5. Dependencies:
  - PocketSphinx/Sphinxbase: Speech recognition
  - Boost: Utilities and data structures
  - OGG Vorbis: Audio decoding
  - TCLAP: Command-line parsing
  - C++17 standard library features

  6. Animation Rules (animation/animationRules.cpp):
  - Maps phonemes to shape sets based on duration and context
  - Uses effort matrices to find closest available shapes
  - Implements tweening logic for smooth transitions
  - Handles special cases like relaxed shapes and basic shape conversions

  The architecture is well-organized with clear separation of concerns, making it maintainable and extensible for different animation software integrations.

⏺ How Rhubarb Lip-Sync Animation Works - Detailed Explanation

  Overview

  The animation system converts recognized phonemes (speech sounds) into mouth shapes through a sophisticated multi-stage pipeline that simulates natural speech patterns. The process involves shape rule generation, rough animation, timing
  optimization, pause handling, tweening, and static segment avoidance.

  1. Phoneme to Shape Rule Mapping (animationRules.cpp, ShapeRule.cpp)

  Each phoneme gets mapped to one or more possible mouth shapes based on linguistic rules:

  - Vowels typically map to single specific shapes:
    - AA (father) → Shape D (wide open)
    - IY (bee) → Shape B (clenched teeth)
    - UW (you) → Shape F (puckered lips)
  - Consonants often have multiple shape options for flexibility:
    - M → Shape A (closed mouth)
    - L → Shapes B, E, F, or H (context-dependent)
    - S/Z → Shapes B or F
  - Special cases:
    - Diphthongs (two-part vowels): Split into two shapes with 60/40 timing
    - Plosives (P, B, T, D, K, G): Include occlusion phase that extends backwards in time (4-12cs before the actual sound)
    - Duration-based rules: Short AH (<20cs) uses Shape C, longer uses Shape D

  2. Rough Animation (roughAnimation.cpp)

  This bidirectional algorithm creates the initial animation:

  Forward pass:
  - Iterates through shape rules chronologically
  - Uses an "effort matrix" to select the closest shape from available options
  - The effort matrix defines transition difficulty between shapes (e.g., A→X is easier than A→F)
  - After each shape, the mouth "relaxes" toward a neutral position

  Backward pass (vowel anticipation):
  - When encountering single-shape vowels, the algorithm backtracks up to 20cs
  - Modifies preceding consonants to anticipate the vowel shape
  - Stops if the anticipating shape becomes too different from the target
  - This creates natural-looking coarticulation effects

  3. Timing Optimization (timingOptimization.cpp)

  Ensures shapes are visible long enough to register:

  Segment identification:
  - Groups shapes into Idle, Closed, and Open mouth states
  - Minimum segment duration: 8cs for visual registration

  Retiming algorithm:
  - Works backwards through the timeline
  - Determines "shape reductions" - which shapes to keep/discard
  - Minimum shape duration: 7cs (prevents flickering)
  - Can extend segments left by up to 6cs to meet minimum duration
  - Distributes time evenly among multiple short segments

  Smart shape selection:
  - Chooses representative shapes based on total duration within timeframe
  - Prefers Shape D over C when both are present (D is more visually interesting)

  4. Pause Animation (pauseAnimation.cpp)

  Handles silence periods based on duration:

  - Very short (<12cs): Hold previous shape
  - Short (12-35cs): Relax mouth gradually (using relax() function)
  - Long (>35cs): Close mouth to Shape X (idle position)

  The system ensures pause shapes differ from the following shape to avoid static appearance.

  5. Tweening (tweening.cpp)

  Currently disabled in the code (returns empty), but the infrastructure supports:

  - Tween shapes between certain transitions (e.g., D→A uses C as tween)
  - Three timing modes:
    - Early: Tween at end of first shape
    - Centered: Tween spans both shapes equally
    - Late: Tween at start of second shape
  - Duration constraints: 4-8cs for tweens

  6. Static Segment Avoidance (staticSegments.cpp)

  Prevents unnaturally long unchanging mouth shapes:

  Detection:
  - Identifies segments lasting >75cs with >3 syllables
  - These appear distractingly static during rapid speech

  Correction algorithm:
  - Identifies flexible vowel rules that can be changed
  - Tests combinations of rule changes (up to 3 replacements)
  - Example: Changes some Shape B vowels to Shape C
  - Uses exponential search to find optimal solution
  - Minimizes sum-of-squares of shape durations

  7. Shape Set Reduction (targetShapeSet.cpp)

  Adapts animation to available shapes:

  - If user only provides basic shapes (A-F), extended shapes (G, H, X) are mapped to closest alternatives
  - Uses the effort matrix to find best substitutes
  - Maintains animation quality with limited shape sets

  Key Design Principles

  1. Natural Movement: The effort matrix ensures transitions follow path of least resistance
  2. Anticipation: Backward propagation creates realistic coarticulation
  3. Visibility: Minimum durations ensure shapes register visually
  4. Variety: Static segment detection prevents monotonous animation
  5. Flexibility: Multiple shape options allow context-sensitive selection
  6. Efficiency: The retiming algorithm balances accuracy with performance

  This sophisticated system produces remarkably natural-looking lip sync by modeling how human mouths actually move during speech, including anticipation, relaxation, and the physical constraints of mouth movement.
